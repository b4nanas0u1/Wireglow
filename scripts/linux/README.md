# Wireglow — Linux x86_64

Запуск: `./Wireglow` или открыть бинарь в файловом менеджере. На главном экране выберите локальный прокси (по умолчанию)
или системный прокси GNOME. Выбор сохраняется между запусками.
Закрытие окна завершает подключение. По умолчанию используется локальный proxy.

Необязательная команда `./install-desktop.sh` регистрирует Wireglow в меню приложений пользователя
через `dev.wireglow.wireglow_ui.desktop` в `$XDG_DATA_HOME/applications`
(по умолчанию `~/.local/share/applications`). GNOME использует эту запись
для иконки окна в панели и переключателе приложений, в том числе на Wayland.
Ярлык запускает непосредственно бинарь. После переноса папки повторите
`./install-desktop.sh`, чтобы обновить пути ярлыка. Для запуска UI он не нужен.
При регистрации старый ярлык прежнего application ID удаляется после успешной
установки нового. Пользовательские профили и настройки не перемещаются.

Папку можно переносить целиком и запускать из любого рабочего каталога.
Корень содержит приложение, `lib/` и `data/` — библиотеки Flutter и assets;
`bin/` — controller, free-turn-proxy и mihomo. `SHA256SUMS` содержит контрольные суммы файлов
(проверка: `sha256sum -c SHA256SUMS` из каталога дистрибутива).

Go, Flutter и Dart SDK для запуска не нужны. Требуются графическая сессия Linux,
системные библиотеки GTK 3 и пользовательский systemd (`systemd-run`).
Для системного прокси нужны GNOME GSettings и dconf. Базовая целевая платформа —
Ubuntu 24.04 amd64; это переносимый каталог, а не установочный пакет.
TUN для Linux экспериментальный. В обычном комплекте из доверенного дистрибутива
выполните `sudo ./install-tun-helper.sh "$(id -u)"`: устанавливается
root-owned `wireglow-tun.service`. В portable-комплекте установка не нужна:
при включении TUN запускается временный helper с запросом прав через polkit;
после отключения он завершается. GUI остаётся обычным пользовательским процессом.
Вход в TUN переподключает сессию и задаёт прямой bootstrap DNS 1.1.1.1.
Другой активный TUN/WireGuard, включая AmneziaVPN, блокирует включение.
Служба и её root-only журнал находятся вне portable-хранилища.
Без установки службы локальный и системный прокси работают как прежде.

Без `portable.json` рядом с приложением профили и runtime-данные сохраняются
в стандартных каталогах пользователя. Для их переопределения доступны
`WIREGLOW_DATA_DIR` и `WIREGLOW_RUNTIME_DIR`.
При наличии `portable.json` все пользовательские данные находятся в `data/`
рядом с приложением, состояние launcher/recovery — в `data/runtime/`.
Временный IPC-сокет создаётся отдельно в закрытом системном runtime и удаляется
watchdog после завершения controller. В portable-режиме
переменные каталогов игнорируются GUI. Явные CLI-флаги controller имеют приоритет.
