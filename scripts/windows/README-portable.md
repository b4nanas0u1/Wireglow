## Portable

Экспериментальный TUN использует комплектный `bin/tun-helper.exe` и временное
повышение прав через UAC; служба и автозапуск не устанавливаются. Другой активный
VPN блокирует включение. Для TURN пока требуется транспорт TCP; UDP-трафик
приложений внутри TUN поддерживается. До начала сетевых изменений helper пишет
закрытый журнал `data/runtime/tun/journal.json`. Защищённая копия mihomo временно
создаётся в `%ProgramData%/Wireglow-Tun/` и удаляется после проверенной очистки.
Драйвер Wintun может остаться установленным, общий драйвер автоматически не удаляется.
При незавершённом recovery журнал не удаляйте; следующий повышенный запуск
сначала проверяет оставшееся состояние. Это не kill switch.

Файл `portable.json` рядом с `Wireglow.exe` включает portable-режим;
его содержимое пока не читается. Все пользовательские данные остаются в
`data/` внутри комплекта: профили, настройки UI и backend, журнал восстановления
прокси. `data/runtime/` содержит блокировки и состояние launcher/recovery.
Только временный IPC-сокет создаётся в отдельной папке `%TEMP%/wg-<run ID>/`
с доступом текущего пользователя и SYSTEM. Watchdog удаляет её после завершения
controller, включая аварийное закрытие GUI. Путь к приложению на адрес IPC не влияет.
Portable GUI игнорирует `WIREGLOW_DATA_DIR` и `WIREGLOW_RUNTIME_DIR`.
Каталоги AppData для этих данных не используются. Папка должна быть доступна
для записи; при ошибке приложение не переходит на системное хранилище.

Перед переносом или обновлением закройте приложение и дождитесь recovery.
Не переносите активную сессию и не применяйте незавершённый журнал восстановления
на другом компьютере. Не запускайте несколько копий с системным прокси.
Сохраняйте пользовательские файлы в `data/`; при обновлении заменяйте только
ресурсы Flutter (`app.so`, `icudtl.dat`, `flutter_assets/`) и файлы поставки.

Сборка: `./scripts/build-windows-portable.ps1`
(или `./scripts/build-windows.ps1 -Portable`). Результат:
`dist/windows-x64-portable/`. Повторная сборка отказывается заменять существующую
portable-папку: сначала переместите её вместе с данными. Обычная
`dist/windows-x64/` сохраняется отдельно.
`SHA256SUMS` проверяйте до первого запуска: пользовательские файлы меняются
во время работы. В архиве CI файлы находятся непосредственно в корне.
