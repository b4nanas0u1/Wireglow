# Режим TUN

TUN экспериментальный. Обычная Linux-сборка использует устанавливаемый helper;
portable-сборки Linux и Windows запускают временный helper с повышением прав.
GUI запускайте от обычного пользователя. Другой активный VPN или туннель блокирует
включение; при смене выходного интерфейса потребуется переподключение.

## Windows portable

Соберите `./scripts/build-windows-portable.ps1` и запустите `Wireglow.exe`.
Выбор TUN запрашивает через UAC разрешение на запуск комплектного `tun-helper.exe`.
Служба и автозапуск не устанавливаются; новый запуск helper требует повышения прав.
В обычной Windows-сборке TUN недоступен: установленная Windows-служба пока не реализована.

Для TURN требуется TCP, выбранный по умолчанию. TURN UDP отклоняется до запуска
движков и запроса UAC. TCP/UDP-трафик приложений внутри TUN и UDP-передача провайдера
direct поддерживаются.

FreeTurn использует HTTPS bootstrap DNS без изменения сохранённого профиля.
Перехваченные DNS-запросы приложений идут через подключение. Ответы AAAA отключены,
но обращения к буквальным IPv6-адресам перехватываются; удалённая поддержка IPv6
зависит от профиля.

Адреса существующих TCP-соединений relay и bootstrap DNS исключаются из захвата.
Другие приложения при обращении к тем же адресам тоже обходят TUN.
Существующие более точные маршруты Windows, включая LAN-подсети, могут иметь
приоритет. Настраиваемая политика маршрутизации/LAN пока не реализована.

Перед переносом или обновлением portable-папки отключите TUN и закройте приложение.
Журнал восстановления находится в `data/runtime/tun/journal.json`; при ошибке
восстановления не удаляйте его ради повторного запуска. Следующий запуск с повышением
прав сначала проверяет оставшееся состояние. Временные привилегированные файлы могут
создаваться вне portable-папки. Драйвер Wintun после отключения может остаться
установленным и автоматически не удаляется.

Это не kill switch: после удаления TUN возвращается обычная сеть. Режим не является
проверенной защитой от любого возможного обхода.

## Linux

Для portable соберите `./scripts/build-linux-portable.sh`. Нужны комплектные
`bin/tun-helper` и `bin/mihomo`, `pkexec` и графический агент авторизации polkit.
Выбор TUN запрашивает права для временного helper; отмена или отказ прерывают
включение. Служба и автозапуск не устанавливаются. Каждый новый запуск helper
может требовать авторизации. Подтверждайте запуск только доверенного дистрибутива.

Для обычной сборки выполните `./scripts/build-linux.sh`, затем из папки
доверенного дистрибутива установите helper для обычного пользователя графической сессии:

```sh
sudo ./install-tun-helper.sh "$(id -u)"
```

Нужны systemd, iproute2 (`/usr/bin/ip`) и `/dev/net/tun`. Устанавливается
`wireglow-tun.service`; GUI не устанавливает службу и не повышает собственные права.
Для обновления привилегированных компонентов или смены разрешённого UID
повторите установку. `SHA256SUMS` выявляет повреждение, но не подтверждает
подлинность недоверенного дистрибутива.

Для TURN UDP требуется Linux 5.6 или новее и разрешённый политикой безопасности
доступ через `pidfd_getfd`. При отказе доступа включение завершается ошибкой.
Обновляйте controller и helper вместе.

Если `/run` смонтирован с `noexec`, portable-helper требует разрешения создавать
mount namespace; при запрете запуск TUN завершается ошибкой.

Вход в TUN переподключает сессию и задаёт FreeTurn прямой bootstrap DNS `1.1.1.1`;
профиль не меняется. Перехваченный DNS приложений использует DoH через подключение.
Ответы AAAA отключены; буквальные IPv6-адреса перехватываются, а связность зависит
от профиля и удалённого узла. Выход из TUN и переключение локального/системного
прокси сохраняют работающие пользовательские ядра.

Отключённые интерфейсы (`DOWN` или `NO-CARRIER`) не блокируют включение.
При ошибке показывается имя обнаруженного активного интерфейса.
В direct-сессиях другие приложения того же UID тоже обходят TUN при отправке UDP
на тот же удалённый адрес и порт. Исключения уже открытых UDP-сокетов фиксируются
при включении и не переносятся автоматически во время сессии.
Короткоживущие сокеты могут закрыться до определения процесса, поэтому
атрибуция уже закрытых сокетов не гарантируется.

При остановке или сбое удаляются собственные сетевые ресурсы. Это не kill switch:
после удаления TUN возвращается обычная сеть. Журнал восстановления находится
в `/run/wireglow-tun/`; не удаляйте его ради обхода ошибки.
Для удаления установленной службы сначала остановите и отключите
`wireglow-tun.service`, разберите оставшийся журнал, затем удалите unit
и каталог установки `/usr/local/libexec/wireglow-tun/`.

## Изолированные проверки

Обычные тесты не включают TUN. Не включайте TUN на хосте и не отключайте его VPN
при автоматической проверке.

### Windows

Сначала запустите Windows Sandbox, затем из корня репозитория:

```powershell
./scripts/test-windows-tun-sandbox.ps1
```

Нужен установленный CLI `wsb`. Проверки выполняются внутри Sandbox и отказываются
работать на хосте. Логи находятся в `.cache/windows-tun-sandbox/<run ID>/output/`.
Набор проверяет IPv4/IPv6 TCP/UDP, DNS, отключение, сбои и восстановление
с настоящим mihomo и синтетическим SOCKS-сервером.

Набор не доказывает реальное подтверждение/отмену UAC, авторизацию/CAPTCHA,
обновление TURN, удалённую связность WG/AWG, сон/пробуждение и сохранение
уже установленного транспорта relay. Проверка обхода использует открытые сокеты
и не гарантирует атрибуцию после их закрытия.

### Linux

Скачайте ядра через `./scripts/download-linux-engines.sh`. Из корня репозитория:

```sh
source scripts/build-env.sh
mkdir -p "$cache_root/bin"
go test -c -o "$cache_root/bin/tun.test" ./internal/infrastructure/tun
unshare --user --map-root-user --net env WIREGLOW_TUN_TEST=1 WIREGLOW_HOST_NETNS="$(readlink /proc/self/ns/net)" \
  WIREGLOW_MIHOMO_TEST_BINARY="$cache_root/engines/linux-amd64/bin/mihomo" \
  "$cache_root/bin/tun.test" -test.v -test.run '^TestIsolated(Tun|EstablishedRelayTCP|EstablishedRelayUDP|EstablishedRelayUDPUnconnected|DirectUDP|TURNUDPIdle)$' -test.timeout 120s
```

Нужен новый network namespace без физических интерфейсов и внешнего подключения.
При запрете пользовательских namespace используйте `sudo unshare --net`.
Тест отказывается работать в namespace хоста. Он проверяет IPv4/IPv6 TCP/UDP,
DNS, обход для открытых сокетов relay, очистку и восстановление с настоящим
mihomo и синтетическим SOCKS-сервером.

Эта проверка не подтверждает графический запрос polkit, обновление TURN-реквизитов
и CAPTCHA, удалённую связность, установленную службу с разными UID и сон/пробуждение.
Синтетические проверки обеих платформ не заменяют сквозной тест удалённого подключения.
