# Режим TUN в Linux

Для обычной Linux-сборки используется необязательная привилегированная служба helper.
Portable Linux запускает временный helper через polkit, без установки службы
или включения автозапуска.
Для Windows подготовлены общие режим, протокол, компилятор конфигурации и
платформенная заглушка; TUN в меню Windows недоступен. Windows-тесты TUN не нужны.

## Установка

Для portable выполните `./scripts/build-linux-portable.sh`. Установка helper
не требуется. Нужны комплектные `bin/tun-helper`, закреплённый `bin/mihomo`,
`pkexec` и графический агент авторизации polkit. Выбор TUN запрашивает права для
временного helper; отмена или отказ прерывают включение. При другом активном VPN
включение отклоняется ещё до запроса прав. Helper завершается после отключения
TUN, потери сокета владельца или смерти controller. Каждый новый запуск helper
может требовать авторизации; служба и автозапуск не устанавливаются.

Подтверждайте запуск только доверенного portable-дистрибутива: первоначальный
запрос polkit разрешает исполнение его helper. Он проверяет UID пользователя и
PID controller, создаёт защищённые временные копии себя и mihomo внутри
`/run/wireglow-tun/`, проверяет закреплённый hash mihomo и перезапускается из
защищённой копии. Временный endpoint принимает только UID/PID запустившего его
controller. Ожидание первой сессии ограничено по времени. После аварии helper
следующий запуск с повышением прав восстанавливает защищённый временный журнал
до включения TUN; перезагрузка удаляет это состояние ядра/runtime. Профили и
настройки UI/backend остаются внутри portable-комплекта.

Для обычной Linux-сборки выполните `./scripts/build-linux.sh`. Из его папки
явно установите helper для числового UID обычного пользователя графической сессии:

```sh
sudo ./install-tun-helper.sh "$(id -u)"
```

Устанавливайте только доверенный дистрибутив. `SHA256SUMS` выявляет повреждение,
но не подтверждает подлинность недоверенного дистрибутива. Установка копирует
helper и mihomo в `/usr/local/libexec/wireglow-tun/` с владельцем root и включает
`wireglow-tun.service`. Нужны systemd, iproute2 (`/usr/bin/ip`) и `/dev/net/tun`.
GUI не устанавливает службу и не повышает собственные права. Эта необязательная
служба относится к обычной Linux-сборке; portable использует временный helper. Обновление привилегированной копии и смена разрешённого UID требуют
явной повторной установки.

Выберите TUN в GUI. Вход в TUN переподключает сессию, задавая FreeTurn обычный
bootstrap DNS `1.1.1.1`; сохранённый профиль не меняется. Интерфейс сообщает об
этом исключении. Выход из TUN и переключение локального/системного прокси
сохраняют работающие пользовательские ядра.

Активный интерфейс TUN/WireGuard блокирует включение, в том числе AmneziaVPN.
Отключённые интерфейсы (`DOWN` или `NO-CARRIER`) не блокируют запуск; ошибка
содержит имя обнаруженного активного интерфейса.
Не отключайте другой VPN при автоматической проверке. При смене выходного
интерфейса или появлении другого туннеля helper останавливает TUN на следующем
heartbeat; переподключение выполняется явно.

## Работа и владение ресурсами

Второй привилегированный mihomo перехватывает IP-пакеты и передаёт их по SOCKS5
в работающий пользовательский mihomo. Секреты WG/AWG остаются только у
пользовательского ядра. Helper полностью компилирует конфигурацию из ограниченного
типизированного запроса; IPC не принимает executable, YAML, providers, скрипты
или пути файлов. Перед обслуживанием проверяются защищённые пути установки и закреплённый SHA-256 распакованного mihomo.
Unix-сокет с правами 0600 в `/run/wireglow-tun/` проверяет SO_PEERCRED:
служба разрешает настроенный UID, а временный portable-helper дополнительно
привязан к PID своего controller. Одно соединение владеет случайным
session ID, request ID и lease 15 секунд; controller отправляет heartbeat каждые
две секунды. API привилегированного mihomo наружу не предоставляется.

Helper владеет таблицей `20220` и приоритетами правил `10217`/`10218`/`10219`/`10220` и перед
запуском отказывает при занятых ресурсах. `auto-route` и `auto-redirect` mihomo
выключены: точную IPv4/IPv6-политику записывает в журнал и устанавливает helper.
Его исходящие сокеты с mark обходят захват. Первым идёт точное правило
PROCESS-PATH/DIRECT для FreeTurn; loopback остаётся в локальной таблице ядра ОС.
Только IPv4-адрес bootstrap-резолвера обходит TUN через исходную таблицу main.
Перехваченный DNS использует fake IP и DoH через работающий прокси. Ответы AAAA
выключены; обращения непосредственно к IPv6 перехватываются и идут по SOCKS.
Работоспособность IPv6 зависит также от WG/AWG-профиля и удалённого узла.

Журнал и конфигурация доступны root в `/run/wireglow-tun/private/`.
Отключение, потеря сокета владельца, истечение lease и авария ядра останавливают
привилегированный процесс и удаляют только совпадающие собственные правила и
случайный TUN-интерфейс. Учитывается IPv6-правило выходного интерфейса mihomo,
которое может существовать при выключенном auto-route. При смене владельца
правила журнал сохраняется и возвращается ошибка. Перезапущенный helper
восстанавливает журнал до приёма соединений. В установленной службе RuntimeDirectoryPreserve сохраняет
журнал при рестарте; перезагрузка удаляет временное состояние вместе с
маршрутами ядра. Это не kill switch: после удаления TUN возвращается обычная
сеть. Helper не меняет default routes хоста, файлы резолвера, системный прокси
или firewall.

Для удаления установленной службы сначала остановите и отключите `wireglow-tun.service`. Разберите
сохранённый recovery-журнал до удаления unit и защищённой папки установки.
Не удаляйте журнал ради обхода ошибки восстановления.

## Проверка

Обычные тесты не включают TUN. Настоящий пакетный тест запускается в **новом
network namespace**, без физических интерфейсов и внешнего подключения:

```sh
source scripts/build-env.sh
go test -c -o "$cache_root/bin/tun.test" ./internal/infrastructure/tun
unshare --user --map-root-user --net env WIREGLOW_TUN_TEST=1 WIREGLOW_HOST_NETNS="$(readlink /proc/self/ns/net)" \
  WIREGLOW_MIHOMO_TEST_BINARY="$cache_root/engines/linux-amd64/bin/mihomo" \
  "$cache_root/bin/tun.test" -test.v -test.run '^TestIsolated(Tun|EstablishedRelayTCP|EstablishedRelayUDP|EstablishedRelayUDPUnconnected|DirectUDP)$' -test.timeout 60s
```

Заранее скачайте закреплённые ядра через `./scripts/download-linux-engines.sh` и
при необходимости создайте `.cache/bin/`. При запрете пользовательских namespace
используйте `sudo unshare --net`. Тест отказывается работать в namespace хоста.
В CI он запускается только в Linux integration job; задания Windows не меняются.

Тест использует настоящий закреплённый mihomo и синтетический SOCKS-сервер.
Проверяются IPv4/IPv6 TCP, UDP, перехват DNS, определение процесса для живых
transport-сокетов relay, обычная очистка, авария ядра, потеря сокета владельца и
отказ при другом туннеле/занятых ресурсах. Правила маршрутизации сравниваются
до запуска и после восстановления. Тесты контроллера также проверяют потерю
helper и отказ переключать в TUN relay без подготовленного bootstrap DNS.

Ограничения: закрытые короткоживущие сокеты могут исчезнуть до определения
процесса mihomo. Тест обхода держит transport-сокеты relay открытыми и не
доказывает атрибуцию уже закрытых сокетов. Настоящий графический запрос прав polkit, обновление TURN-реквизитов
FreeTurn, повторная CAPTCHA, удалённое подключение, установленная служба с
разными UID, сон/пробуждение и Windows TUN этой изолированной проверкой не
подтверждены. Синтетический SOCKS-тест не заменяет сквозной тест удалённого VPN.

## Результаты проверки — 2026-10-21

Linux x64, Go 1.27.1, Flutter 3.47.7 / Dart 3.13.5, mihomo v1.19.32:
прошли Go vet для Linux и Windows, Go-тесты Linux, lifecycle/recovery-интеграции,
race-проверки controller/TUN, Flutter analyze/tests, Dart↔Go IPC smoke и полная
сборка Linux. Пакетный тест выполнялся только через
`unshare --user --map-root-user --net` с синтетическими endpoint. Helper на
ноутбуке не устанавливался, трафик хоста не перехватывался.

Диагностика также обнаружила и исправила проблему атомарности в существующем
тесте часов владельца и слишком длинный путь сокета smoke-скрипта. Его временное
состояние IPC теперь размещается в коротком системном временном каталоге.
Настройки системного прокси, VPN и firewall при диагностике не менялись.

Проверка portable-bootstrap дополнительно запускает настоящий helper в
синтетическом chroot внутри mount/PID/network namespaces. Проверяются защищённый
re-exec, отключение, потеря сокета владельца, завершение процесса, удаление
бинарников/журнала и сохранение правил маршрутизации без создания файлов службы.
Локальная команда после сборки `.cache/bin/tun-helper` и загрузки ядер:

```sh
unshare --user --map-root-user --mount --net --pid --fork python3 \
  internal/infrastructure/tun/testdata/portable_helper.py "$PWD" "$(readlink /proc/self/ns/net)"
```

Тест моделирует уже выданную авторизацию и не проверяет графический диалог
polkit. В CI он выполняется только в Linux через `sudo unshare`.

Portable использует отдельный endpoint `portable-<PID controller>.sock` и не переиспользует установленную службу. Helper этой версии разделяют блокировку/журнал сетевой сессии: неактивный постоянный helper не мешает portable, а два helper не могут одновременно включить TUN. Bootstrap-тест также проверяет сосуществование с неактивным постоянным helper и отмену до Start.

Меню выбора режима на главном экране и в настройках обновляет доступность
режимов через controller перед каждым открытием. VPN, включённый после старта
клиента, блокирует TUN при следующем открытии меню. При ошибке проверки меню
не открывается; проверка при активации TUN также остаётся обязательной.

На Linux с `noexec` для `/run` portable-helper создаёт отдельное пространство
монтирования и исполняемый tmpfs только внутри него. Флаги `/run` хоста
не меняются. Временные образы удаляются при выходе; установка службы не нужна.
Для этого повышенному helper требуется разрешение создавать mount namespace.
При отказе активации UI показывает диагностическую причину TUN-адаптера.

Ошибки probe содержат безопасную причину: HTTPS/TLS, UDP SOCKS, DNS-ответ
или тайм-аут. Исходные URL, данные профиля и вывод ядер не публикуются.
Это уточнение диагностики само по себе не означает исправления сетевого отказа.

В TUN-сессии внутреннее WG-ядро использует собственный DNS в режиме
`redir-host`: `https://1.0.0.1/dns-query#PROXY`. Оно не обращается к системному
resolver, который внешний TUN может снабжать fake-IP адресами из другой
таблицы сопоставлений. Локальный и системный proxy-режимы сохраняют прежний DNS.
Синтетический тест с настоящим pinned mihomo проверяет DNS через SOCKS и
возврат реального IP. Формат настройки: [документация mihomo](https://wiki.metacubex.one/ru/config/dns/).

Для HTTPS probe диагностика различает ответ HTTP CONNECT от локального
proxy, этап TLS и чтение HTTPS-ответа. EOF, reset/refused/unreachable,
сертификаты и тайм-ауты публикуются как фиксированные категории; неизвестная
ошибка показывает только тип Go, без исходного текста с URL.

До захвата TUN helper добавляет точные правила `10218` для уже открытых
TCP-сокетов FreeTurn: семейство, локальный и удалённый адреса и оба порта,
с lookup main. Открытые TCP-потоки нельзя впервые передать userspace TCP-стеку
посреди соединения: PROCESS-PATH срабатывает слишком поздно для такого потока.
Обходы записаны в журнале; cleanup удаляет только совпадающие правила.
Новые соединения relay по-прежнему обходят прокси через PROCESS-PATH/DIRECT.
Изолированный regression-тест сначала открывает TCP через veth в соседний
namespace, затем включает TUN и проверяет сохранение потока и cleanup при crash.

Диагностика Linux mihomo собирает только фиксированные категории предупреждений
(DNS, отказ соединения, timeout и т. п.). Строки вывода ограничены 4096 байтами
и отбрасываются после классификации, исходные логи на диск не записываются.
Перед активацией TUN категории сбрасываются. После отказа UI добавляет
категории mihomo и, для portable, число точных TCP-обходов и сохранившихся
сокетов. Отсутствие предупреждений не доказывает исправность: некоторые
ошибки после lazy-handshake mihomo не журналирует.

Для уже открытых UDP-сокетов relay helper добавляет правила `10217`:
`uidrange <UID>-<UID> ipproto udp sport <порт> lookup main`. Это сохраняет
исходящий адрес и порт: захват через userspace DIRECT создавал другой UDP
endpoint. Порты выбираются только по fd/inode процесса FreeTurn, UID сокета
обязан совпадать с владельцем. При совпадении порта с другим процессом
активация отклоняется. Dual-stack wildcard UDP получает правила IPv4 и IPv6.
UDP-правила входят в журнал и удаляются только по полному совпадению.
Регрессия проверяет обмен с peer до/после TUN, неизменность source endpoint
для connected и unconnected UDP и очистку после аварии engine.

Для direct правило `10216` выбирает `to <peer-IP> uidrange <UID>-<UID>
ipproto udp dport <peer-порт> lookup main`. Исходный порт не ограничен: новые и
пересозданные сокеты идут мимо TUN с первого пакета. Peer разрешается до запуска
FreeTurn; один и тот же числовой IP передаётся FreeTurn и helper на всю сессию.
Сохранённый профиль не меняется; при переподключении домен разрешается заново.
Другие приложения того же UID тоже обходят TUN при отправке UDP на этот точный
endpoint. Правило записывается в журнал до установки и удаляется только по
полному совпадению. Изолированные тесты IPv4/IPv6 создают новые сокеты после
активации, проверяют сохранение исходного порта, ограничения UID/порта назначения
и очистку после аварии engine.

Известное ограничение VK/TURN: исключения UDP строятся по снимку на момент активации
TUN. Новые и пересозданные сокеты FreeTurn не получают исключений ядра во время
сессии и зависят от правила процесса в mihomo. Исключения старых портов остаются
до очистки TUN. FreeTurn может пересоздавать транспорт при восстановлении
потоков; обработка смены сокетов VK/TURN пока не завершена.
