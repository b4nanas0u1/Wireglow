# Wireglow — Flutter UI

Flutter-пакет и CMake-проекты называются `wireglow_ui`, корневой виджет —
`WireglowApp`. Linux application ID — `dev.wireglow.wireglow_ui`,
desktop-файл — `dev.wireglow.wireglow_ui.desktop`. При регистрации новый
ярлык заменяет ярлык прежнего application ID. Каталоги профилей и настроек
сохраняются для совместимости.

Локальный gRPC-контракт хранится в `../proto/controller.proto`, namespace —
`wireglow.control`. Go-код обновляется командой `./scripts/generate-grpc.sh`
из корня репозитория, Dart-код — `./scripts/generate-dart-grpc.sh`.
Для уже заполненного кэша зависимостей Dart-генератор принимает `--offline`.
Сгенерированные Dart-файлы находятся непосредственно в `lib/controller/gen/`.

Название приложения задаётся в `lib/app_info.dart` (`appName`). Сборка использует
его в интерфейсе, заголовках Linux/Windows-окон, имени бинаря комплекта и desktop-ярлыке. Linux build tree сохраняет имя `wireglow_ui` для Flutter tooling. После изменения названия
пересоберите приложение и повторно зарегистрируйте Linux-ярлык при необходимости.

Сборка Linux UI вместе с Go controller выполняется из корня репозитория:

```sh
./ui/build-linux.sh
```

Windows UI собирается из каталога `ui`:

```powershell
flutter build windows --release
```

Результат: `build/windows/x64/runner/Release/Wireglow.exe`. Для переноса нужен
весь каталог `Release`, включая DLL и `data`, а не только exe.
Windows runner использует комплектную иконку из `windows/runner/resources/`.
Это сборка UI: controller и сетевые ядра в неё пока не упаковываются.
UI находит controller и ядра в `bin/` рядом со своим executable.
Переменные `WIREGLOW_CONTROLLER`, `WIREGLOW_RELAY`, `WIREGLOW_MIHOMO`
остаются необязательными переопределениями для разработки.
Для изолированных данных и runtime доступны `WIREGLOW_DATA_DIR` и
`WIREGLOW_RUNTIME_DIR`. Прежний префикс переменных окружения заменён на
`WIREGLOW_`; старые имена больше не читаются. Каталоги по умолчанию не менялись.

На вкладке «О клиенте» отображаются версия, короткий хеш коммита, тег текущего
коммита (если есть) и время сборки в UTC. Здесь же доступны версии mihomo и
free-turn и ссылки на их репозитории GitHub. Поля доступны только для чтения,
значения и ссылки можно выделять и копировать. Скрипт встраивает эти данные
через `APP_VERSION`, `APP_COMMIT`, `APP_TAG` и `APP_BUILD_TIME` (`--dart-define`).
При сборке без Git хеш отображается как «неизвестен»; при запуске напрямую через
Flutter метаданные можно передать теми же параметрами. Версии и репозитории
ядер скрипт берёт из общего `internal/infrastructure/engines/manifest/manifest.yaml`
через утилиту `engine-manifest` и передаёт через `MIHOMO_VERSION`,
`MIHOMO_REPOSITORY`, `FREE_TURN_VERSION`, `FREE_TURN_REPOSITORY`. Без этих
параметров версии ядер отображаются как «неизвестна».

Для сборки нужны Go, Flutter/Dart и системные зависимости Flutter для целевой платформы. Сборочные скрипты хранят кэши Go, Dart, инструменты генерации и загруженные ядра в `.cache/` в корне репозитория. Соседние рабочие папки не используются. Flutter SDK можно установить в `.cache/flutter/` или добавить в `PATH`.

Готовый комплект запускается бинарём `Wireglow` / `Wireglow.exe` из корня папки.
`./ui/run-linux.sh` — вспомогательный запуск Linux build tree для разработки.
В Linux-комплекте `./install-desktop.sh` отдельно создаёт необязательный
ярлык меню, который указывает непосредственно на бинарь.

Язык интерфейса выбирается в шапке: System / English / Русский. По умолчанию
используется системный язык; если он не поддерживается, используется английский.
Выбор применяется без перезапуска и сохраняется в `wireglow/ui-settings.json`
в системном каталоге настроек (Linux: `$XDG_CONFIG_HOME` или `~/.config`).
Сообщения ошибок backend показываются без перевода. Словари интерфейса находятся
в `lib/l10n/app_en.arb` и `app_ru.arb`; Flutter генерирует классы переводов
при сборке или командой `flutter gen-l10n`.

Справа от выбора языка находится кнопка цветовой темы: системная, тёмная
или светлая. Тема Wireglow использует графитовые поверхности и янтарный акцент
в тёмном режиме, тёплые светлые поверхности и медный акцент в светлом.
Выбор применяется сразу без переподключения и сохраняется отдельно в
`wireglow/theme-settings.json` в системном каталоге настроек. По умолчанию
приложение следует теме ОС. Меню темы и языка имеют одинаковые размеры.
При первом запуске с новым расположением существующие файлы языка и темы из
прежнего каталога копируются в `wireglow`, если соответствующего нового файла
ещё нет. Уже сохранённые настройки Wireglow имеют приоритет; старые файлы
остаются для отката. Это не меняет расположение профилей и данных backend.

В шапке рядом с выбором языка находится компактное меню режима прокси:
локальный прокси (по умолчанию) и системный прокси. Выбор хранится backend в
`client-settings.json` в каталоге данных клиента и действует для всех профилей.
При изменении режима backend меняет только системные настройки прокси через
журнал восстановления. Free-turn и mihomo продолжают работать, адрес локального
прокси и сессия сохраняются. Ошибка изменения настроек показывается в интерфейсе;
частичное включение откатывается. При незавершённом восстановлении режим отмечен
как неизвестный, журнал сохраняется для повторной попытки. Повторные команды
на время переключения блокируются.
Адрес локального HTTP/SOCKS-прокси можно скопировать рядом со статусом.
Системный прокси на Linux требует GNOME; причина недоступности отображается
в интерфейсе.

Вкладка «Настройки» содержит общие адреса HTTP/SOCKS-прокси mihomo и relay
FreeTurn. По умолчанию это `127.0.0.1:17891` и `127.0.0.1:17890`.
Поддерживается host `127.0.0.1` и порты 1–65535; порты должны отличаться,
Порт API mihomo также настраивается (по умолчанию `17892`); все три порта
должны отличаться. Кнопка «Сохранить» записывает
адреса в `client-settings.json`; они применяются при следующем подключении.
Активная сессия продолжает работать с прежними адресами. На этой же вкладке
можно изменить режим прокси и язык: эти изменения применяются сразу.

«Вернуть значения по умолчанию» после подтверждения восстанавливает оба адреса, порт API mihomo,
локальный режим прокси и системный язык. Профили сохраняются. Если соединение
активно, системный прокси выключается через штатное восстановление, а ядра
продолжают работать с прежними адресами до переподключения.

Настройки разделены на блоки «Общее» (режим прокси и язык), «Сеть»
(HTTP/SOCKS-прокси и порт API mihomo) и «Релей» с подблоком
FreeTurn (локальный адрес relay).
